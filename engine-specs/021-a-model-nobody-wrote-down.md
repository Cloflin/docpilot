# 021 — Модель, которую никто не писал

> **Кратко.** Молчание в конфиге значило «обойди десять бесплатных id», и это
> ставило на провод модели, которых нет ни в одном файле, который читает автор
> сайта. Три дефолта переезжают: `openrouter` получает собственную модель
> `openrouter/free` вместо пула, `chatModels` перестаёт резолвить пул из
> умолчания и слушает только `chat.models` или `chat.model: 'free'`, а
> `chat.chain` уезжает с `'auto'` на `false`. Побочный эффект, который чуть не
> прошёл незамеченным: дневной леджер на 50 запросов спрашивал «есть ли список?»
> вместо «это бесплатный тариф?» и выключился бы вместе с пулом.

## Problem

HAR с `docpilot-nine.vercel.app`, вопрос про внешний вид панели. На проводе — семь
`:free` моделей подряд:

```
openai/gpt-4o-mini                        404
nvidia/nemotron-3-ultra-550b-a55b:free    200
minimax/minimax-m3:free                   200, 200, 404
poolside/laguna-s-2.1:free                404
nvidia/nemotron-3.5-lightning:free        404
inclusionai/ling-3.0-flash-fin:free       404
nvidia/nemotron-3-super-120b-a12b:free    200 — ответ читателю
```

Транспортную половину этого разобрала 020: тело отказа не читалось,
параметрический 404 классифицировался как «модель снята с каталога», и ротация
покупала один и тот же отказ по разу на модель. Осталась вторая половина
вопроса, которую 020 не задавала: **откуда вообще взялся список**.

Ответ в конфиге сайта — `chat.models` из восьми записей. Но это не объясняет
жалобу целиком, потому что тот же список библиотека выдаёт САМА:

```js
// src/config.js
export function chatModels(docPilot) {
    if (ownChatModels(docPilot)) return [...docPilot.chat.models]
    return isAutoModel(docPilot.chat.model) ? freePoolFor(docPilot.chat.provider, 'chat') : null
}
```

`isAutoModel` считает одинаковыми `null`, `''`, `'auto'` и `'free'`. Первое из
них — это `chat: {provider: 'openrouter'}` и больше ничего, то есть install из
одного ключа, который документация называет кратчайшим путём. Такой деплой
отправляет запросы к десяти моделям, ни одна из которых не написана нигде в его
конфиге.

### Почему это не «фича, а не баг»

Аргумент за пул настоящий: бесплатный id — это общая квота, его `429` сообщает,
сколько людей спрашивает прямо сейчас, а не что-то про модель. Пин одной модели
покупает панель, которая работает до чужого трафика.

Но у него есть цена, которую 020 измерила: тело у всех членов пула ОДИНАКОВОЕ,
поэтому отказ, относящийся к запросу, а не к модели, покупается по разу на
члена. Пять 404 подряд в строках 7–11 — ровно это. На тарифе, который считает
запросы, ротация в такой ситуации не резервный путь, а множитель.

И вторая цена, которая не измеряется, а называется: **отладка**. Читатель
конфига видит `provider: 'openrouter'`. В консоли браузера — `nvidia/nemotron-…`.
Между этими двумя фактами нет ни одной строки, которую можно прочитать.

### Провайдерский чейн — то же самое уровнем выше

`chat.chain` шипнулся `'auto'` одним релизом раньше: окружение с двумя ключами
обходило оба. Аргумент тот же и цена та же — запрос уходит сервису, которого нет
в конфиге, и `OPENAI_API_KEY`, выставленный для соседнего проекта, меняет,
куда идёт вопрос читателя.

## Decision

**`openrouter` получает табличную модель по умолчанию: `openrouter/free`.**

Прямолинейное «убрать пул» ломает install из одного ключа: `chatModel` был
`null`, поэтому без пула `chatModelOf` не возвращает ничего и `assertChat`
останавливает сборку — включая fall-through `CHAIN_FALLBACK = 'openrouter'`, то
есть пустое окружение. `openrouter/free` — это тот же аргумент, отвеченный на
хоп ближе к пулу: собственный роутер сервиса по бесплатному тарифу, выбирающий
свободную модель на запрос и пропускающий насыщенные. **Один id, один запрос.**

**`chatModels` читает `poolNamed`, а не `isAutoModel`.** Новое resolved-only
поле рядом с `providerAuto`/`modelAuto`, считается в `resolveChat` ДО строки,
которая затирает `'free'` в `null` — иначе вопрос уже не задать. Истинно только
для двух слов, `'free'` и `'auto'`; `''` не входит, потому что пустая строка —
это ключ, который забыли заполнить, а не пул, который попросили.

`??` в обоих флагах — правило идемпотентности из `switches.js`: отрезолвленная
запись является законным входом. Заодно закрыта та же дыра у `modelAuto`, где её
не было: `merged.model == null` после заполнения дефолта читался как «автор
назвал модель», и `ladderTier` сортировал бесплатного члена на платную ступень.
Дефект старше этой правки и расширяется ею на всех провайдеров сразу, поэтому
чинится тем же коммитом.

**Член чейна за головой не получает пул.** `spec.models` или ничего. Раньше
`chain: ['openrouter']` означал десять id на члене, которого автор написал одним
словом.

**`chat.chain` шипается `false`.** `'auto'` пишется словом.

**Дневной леджер спрашивает про тариф, а не про список.** Это место чуть не
прошло молча:

```js
function freeChatPool(docPilot) {
    if (ownChatModels(docPilot)) return false
    return Boolean(chatModels(docPilot))   // «есть ли список?»
}
```

После правки `chatModels` для `{provider: 'openrouter'}` возвращает `null` →
`llm.freePool` ложно → `session.js` не заводит потолок → `budget.js` перестаёт
рационировать, и деплой, у которого по-прежнему 50 запросов в сутки, едет
полностью агентно. Это перерасход из 020, зашедший с другой стороны. Вопрос
теперь тот, который члены чейна задавали всегда: публикует ли ПРОВАЙДЕР
бесплатный каталог, и отказался ли автор от него, назвав модель.

**Проба возможностей расширяется по тому же признаку.** `budget.probe: 'auto'`
пропускала пробу «где сконфигурирован пул», читая длину списка. Обоснование
всегда было про СЕРВИС — «пул конфигурируется только для хостед
OpenAI-совместимого сервиса, чьи модели умеют инструменты по построению», — а
бесплатный каталог остаётся тем же сервисом, сколько бы id ни уехало в браузер.
Без этой правки табличный дефолт выкупил бы обратно по запросу на сессию у всех,
кто не назвал ничего.

## Consequences

| конфигурация | было | стало |
|---|---|---|
| `{provider: 'openrouter'}` | 10 id, обход в браузере | `openrouter/free`, один id |
| `{provider: 'openrouter', model: 'free'}` | 10 id | 10 id — без изменений |
| `{provider: 'openrouter', models: […]}` | свой список | свой список — без изменений |
| `{provider: 'openrouter', model: 'gpt-4o-mini'}` | одна модель | одна модель — без изменений |
| два ключа в окружении, `chain` не написан | обход обоих | первый, и только он |
| дневной потолок 50 у первой строки | заводится | заводится |
| проба на первый вопрос сессии у первой строки | пропускается | пропускается |

Мигрировать нечего: сборка не падает ни на одной прежней конфигурации, потому
что табличный дефолт закрывает случай, ради которого `assertChat` и написан.
Кто полагался на обход пула из умолчания, пишет `model: 'free'`.

### Чего это не решает

- **Настройки аккаунта.** allowed-providers и ZDR вырезают эндпоинты до того,
  как до модели дойдёт запрос — `failed_routing_step: "Filter by Guardrails"`.
  Одна модель отказывает по той же причине, что и десять; разница только в том,
  что теперь это один отказ, а не десять.
- **Роутер — не гарантия.** `openrouter/free` выбирает за нас, и что именно он
  выбрал, видно только в поле `model` ответа. Это осознанный обмен: выбор,
  сделанный сервисом на его стороне, дешевле обхода, сделанного браузером на
  чужой квоте. Кому нужен пин — пишет id.
- **Embed-половина по-прежнему резолвит пул из молчания**, и иначе не может:
  `docpilot index` перебирает бесплатные эмбеддеры, чтобы найти отвечающий, и
  спросить автора во время сборки не у кого. Асимметрия названа в
  `docs/guide/providers.md`.
