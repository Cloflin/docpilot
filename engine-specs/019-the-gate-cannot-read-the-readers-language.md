# 019 — The gate cannot read the reader's language

> **Кратко.** `guard.mode` по умолчанию был `'dense-only'`: гейт отказывает до
> вызова модели, кроме одного случая — векторless-развёртывание. Измерено на
> собственном индексе пакета: русский вопрос про установку получил G 0.21 против
> tau 0.41, хотя строка «closest pages» того же вердикта назвала три страницы, на
> которых ответ есть. Лексический канал равен нулю по построению для любого
> вопроса не на языке корпуса — порогом это не закрывается ни для одного языка,
> и языков у читателей больше одного. Умолчание меняется на `'off'`: вердикт
> по-прежнему считается и пишется в запись, решает не заканчивать ход только
> модель.

## Problem

**Гейт сконструирован так, что не может отличить «вопрос не по теме» от
«вопрос на другом языке».** `lexicalCoverage` (`gate.ts`) — это доля редких
слов вопроса, встретившихся в найденном тексте; `L` для вопроса на языке,
которого нет в корпусе, равна нулю не потому, что вопрос не по теме, а потому,
что токенайзер не видит ни одного общего слова. `G = wDense·D + wLexical·L`
теряет 25% своего веса на этом канале мгновенно, и оставшемуся плотному каналу
приходится в одиночку тянуть порог, откалиброванный на распределении, где у
позитивов L почти всегда положительна.

**Измерено на боевом индексе (`3dc7547a`, 493 чанка,
`nvidia/nemotron-3-embed-1b:free`, tau 0.41, замер через собственный
`/ai/v1/embeddings` прокси сайта, без ключа):**

| вопрос | L | D | G | вердикт |
|---|---|---|---|---|
| как мне установить к себе на **сейт**? (опечатка) | 0 | 0.341 | 0.256 | refused |
| как мне установить к себе на сайт? | 0 | 0.615 | 0.461 | passed |
| С чего начать? | 0 | 0.280 | 0.210 | refused |
| Как начать работу с DocPilot? | 0.33 | 0.990 | 0.826 | passed |
| How do I install it on my site? | 1 | 0.799 | 0.849 | passed |

Опечатка в одном слове двигает G на 0.2 у вопроса, который не содержит вообще
никакой лексики корпуса — потому что весь вес держится на плотном канале в
одиночку, и там нет запаса. Упоминание продукта («DocPilot») чинит вердикт не
потому, что вопрос стал понятнее, а потому, что это единственное слово в
вопросе, которое лексический канал вообще может увидеть.

**Что уже покрыто, что нет.** `vocabulary` (`docs/reference/config.md#vocabulary`)
закрывает случай одного алфавита — читатель называет продукт другим словом.
Ничего не закрывает случай другого алфавита: карту слов пришлось бы вести на
каждом языке, которым пользуются читатели сайта, заранее зная все эти языки.

**Прецедент в этом же пакете.** CHANGELOG 1.2.0, спека 014: десять из десяти
вопросов про отсутствующую фичу прошли гейт с G от 0.735 до 1.000 — «no
threshold separates them, which is why this is an instruction and not a
calibration». Эта спека — то же движение для оси языка: решение переносится с
порога на модель, потому что порог для этого не создан.

## Research

**Что гейт реально ловит по умолчанию** (`docpilot/calibration.rag.json`, tau
0.41, 240 негативных проб):

| страта | что это | ловится до модели |
|---|---|---|
| N4 | явный офф-топик («стих про море») | 96.7% |
| X | заскоуплено, золото вне скоупа | 90.0% |
| N3 | офф-домен технический | 73.3% |
| N5 | офф-домен после легитимного хода | 53.3% |
| N1 | соседний продукт | 10.0% |
| P | заскоуплено, лексика пересекается, ответа нет | 10.0% |
| N6 | цитата из корпуса + офф-домен запрос | 6.7% |
| N2 | правдоподобный, но не существующий API продукта | 0.0% |
| **всё** | | **42.5%** |

138 из 240 негативов и так доходят до модели сегодня. Класс, который гейт не
ловит вообще (N2), — тот, где неверный ответ дороже всего; класс, который
ловится лучше всего (N4), — тот, который модель и сама отказывает тривиально.
Верхняя граница over-refusal — 1.58% на 169 англоязычных позитивах: из 597
проб набора десять кириллических, и ни одна не входит в страту `U` — граница
ничего не говорит о населении, для которого пишется эта спека.

**Почему не квота-зависимый гейт.** Рассмотрено и отклонено: один и тот же
вопрос отказывал бы вечером и отвечал утром, и два отчёта `eval` перестали бы
быть сравнимыми — а этот пакет специально штампует происхождение каждого
отчёта, чтобы сравнимость держалась. Контроль стоимости уже есть в
`budget.ts` — рационирование на `oneShotBelow` 15 и `rotateAbove` 6, ни разу не
отказывающее вопрос целиком.

**Почему не минимальный абсолютный порог по косинусу.** Это и есть
языкозависимый инструмент, который снимается. На этом индексе вопрос по теме
на русском не поднимается выше maxCos 0.15–0.29, а по теме на английском
достигает 0.36 — порога, разделяющего эти два случая, не существует.

## Decision

**Оба места умолчания меняются вместе.** Умолчание задублировано и должно
двигаться синхронно:

```js
// src/config.ts — DEFAULTS (сборка)
guard: {mode: 'off', tau: null, tauLexical: null, supportMinIdentifiers: 3},

// src/theme/docpilot/session.ts — DEFAULTS (браузер)
guard: { mode: 'off', tau: null, tauLexical: null, supportMinIdentifiers: 3 },
```

`GUARD_MODES` (`src/config.ts`) переставлен в порядок `['off', 'dense-only',
'calibrated']` — тот же порядок, что теперь в таблице `docs/reference/
config.md` и в юнион-типе `types/config.d.ts`; принимает все три значения
по-прежнему, `assertGuard` не бросает ни на одном. `enforces()`
(`gate.ts`) не менялся — только его доккомментарий, называвший `dense-only`
умолчанием.

**Сигнал «результаты слабые» больше не завязан на `guard.mode`.**
`session.ts`, строка, которая решает, писать ли `noStrongMatches`/`wouldWiden`:

```js
// было
if (g && cfg.guard.mode !== 'off' && !g.pass) { ... }
// стало
if (g && !g.pass) { ... }
```

Это не побочный эффект, а отдельно найденная и починенная регрессия. Функция
`fillResults`, где это условие живёт, вызывается ровно из трёх мест — search-only
(`chat: false`), дневная квота исчерпана без написанного текста, оборвавшийся
транспорт — и во всех трёх сгенерированного ответа нет вообще, так что
предложение «здесь ничего не совпало сильно» истинно всегда, когда до него
доходит очередь, независимо от `guard.mode`. Прежнее условие молча гасило эту
строку на каждом дефолтном развёртывании — включая site search-only, для
которого этот вердикт единственный существующий сигнал,
`docs/guide/free-tier.md` называет это свойством именно этой конфигурации.
Регрессию ловят `test/search-only.test.js`, кейсы на `noStrongMatches`/
`wouldWiden`.

**`docpilot eval` уважает режим, а не жёстко считает отказом любой провал
вердикта.** `src/eval/run.ts`:

```js
if (enforces(docPilot.guard.mode, g.mode) && !g.pass) {
  row.observed = g.wouldPassUnscoped ? 'refuse:out-of-scope' : 'refuse:no-evidence'
  ...
}
```

При `guard.mode: 'off'` (умолчание) негативная проба теперь доходит до модели
и оседает как `refuse:not-answerable` или `answer` — то же измерение, которое
делает боевая панель. **Отчёты через эту границу несравнимы**; `meta.guardMode`
теперь пишется в отчёт рядом с существующими `tau`/`guard.source`, и заголовок
markdown-отчёта печатает строку `guard.mode` отдельно от `guard.denseMode`
(разные оси: одна — как измеряется расстояние, другая — заканчивает ли
провалившийся вердикт ход).

**Заметка `readiness()`/`doctor` переписана**, а не просто снята:
`src/config.ts` — старая заметка срабатывала только на `dense-only` внутри
`embed.lexicalOnly`; новая срабатывает на `'off'` (умолчание) при наличии
чат-провайдера и говорит, что теперь верно для ЛЮБОГО развёртывания — вопрос не
по теме тратит запрос модели прежде, чем это станет известно, что на общем
бесплатном тарифе — один из примерно пятидесяти в день на весь сайт. Отдельная
заметка остаётся для явного `dense-only` на vectorless-сайте — на этой форме
он деградирует ровно до `'off'`, и об этом стоит сказать тому, кто выбрал
`dense-only` намеренно, а не унаследовал.

## Why it fits

Гейт как механизм не меняется вовсе: `verdict()`, `denseSeparation`,
`lexicalCoverage` считаются на каждом ходу, как считались. Меняется единственная
точка — `enforces()` — и она уже существовала именно для этого решения:
«вердикт всегда посчитан, отказывает не всегда» было архитектурным инвариантом
до этой спеки (комментарий над `enforces` уже писал «All three still score every
turn and record it»), спека лишь двигает, какое из трёх значений — умолчание.

## Cost and risk

**Цена — по модельному запросу на вопрос, для которого в корпусе ничего нет, на
каждом развёртывании, а не только на vectorless.** На общем бесплатном тарифе
(≈50 запросов в день на весь сайт) это заметно; `budget.ts`'s рационирование
(`oneShotBelow`, `rotateAbove`) остаётся единственной защитой от исчерпания, и
она не отказывает вопрос — только сокращает, во что выливается его обработка.

**Риск — N2 не ловится вообще ни при каком режиме, кроме модельного отказа.**
Таблица в Research: правдоподобный, но не существующий API продукта проходит
гейт со счётом 0%. Это не регрессия этой спеки — так было и при `dense-only` —
но именно этот класс теперь целиком зависит от того, что модель откажется
писать про несуществующий метод, а не от порога. Сторож — `hallucinated`
(`src/eval/metrics.ts`), который меряет не гейт, а честность процитированного.

**Риск — свидетельство есть, ответ может быть слабым.** `'off'` снимает
отказ ДО модели, но не гарантирует, что сырой ретрив вопроса найдёт нужные
чанки — короткая фраза на другом языке может остаться плохо ранжированной
(спека 018 закрывает частный, но самый частый случай — перефраз одного из
сконфигурированных опенеров).

**Условие отката.** `guard: { mode: 'calibrated' }` — одна строка, возвращает
дореформенное поведение целиком, для сайта с одноязычным корпусом и набором
проб под него.

## Checks

- `test/no-embed.test.js`: умолчание — `'off'`, не `'dense-only'`;
  `enforces('off', ...)` — `false` на обоих режимах ретрива; новая заметка
  `readiness()` содержит текст `guard.mode is 'off' — the default since 1.3`;
  отдельный кейс — явный `dense-only` на vectorless-сайте печатает свою,
  отдельную заметку про деградацию.
- `test/search-only.test.js`: `noStrongMatches`/`wouldWiden` остаются `true`/
  `false` в прежних сценариях — регрессия строки `session.ts:1936` (теперь без
  номера, условие сузили).
- `test/hybrid.test.js`: сценарий с явным `guard: { mode: 'calibrated' }`
  по-прежнему отказывает до модели — старое поведение доступно, просто не по
  умолчанию.
- `test/docpilot.test.js`, `11d`/`11e`: `## All defaults` и таблица
  `## Parameters` в `docs/reference/config.md` исполняются и сверяются с
  `DEFAULTS` — `guard.mode` в обоих `'off'`.
- `npm run typecheck`, `npm run verify` — после переиндексации (см. ниже).

## What this does not do

**Не убирает гейт из публичного питча.** README, описание на npm,
`docs/guide/comparison.md` и остальные страницы по-прежнему называют
калиброванный гейт как опцию — `guard.mode: 'calibrated'` даёт тот же
результат, что был умолчанием до этой спеки, request for request.

**Не меняет, что вердикт считается и пишется.** `turn.gate` заполняется на
каждом ходу независимо от `guard.mode`; feedback-запись, отчёт `eval`,
`?dpdebug=1` — все продолжают видеть настоящий `G`/`D`/`L`, просто отказ по
нему теперь опционален.

**Не решает языковой разрыв в ранжировании ретрива напрямую.** Снятие гейта
даёт вопросу дойти до модели; насколько хорошим будет ретрив для этого
вопроса — отдельный вопрос, который спека 018 частично закрывает для
перефразов сконфигурированных опенеров и не закрывает для остальных.
