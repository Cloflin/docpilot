# DocPilot 2.0 — the facts sheet

The single list of what 2.0 changes, for the docs, the changelog and the
comparison page. Every item is in the code on branch `v2`; specs 029–037 hold the
reasoning. **Chat behaviour for readers is unchanged** — every change below is
under the hood, or is the owner's tooling.

## Two installs

| | static (`runtime: 'browser'`, default) | server (`runtime: 'server'`) |
|---|---|---|
| where the turn runs | the reader's browser | `@cloflin/docpilot/server` on the owner's server |
| what the page gets | the index (shards, vectors, df), the prompt, the thresholds | a shell manifest (pages, sections) and the SSE stream |
| key | behind the `/ai` proxy | on the server only |
| set up | `npx docpilot index` + the proxy | `npx docpilot serve --dir=<site>` or `createDocPilotServer` |

`npx docpilot init` now asks which install (`--runtime=browser|server`) and prints
the block to paste; for a server install, how to run it and the two secrets.

## Server install (specs 031, 033)

Operator settings, in `docPilot.server` (server-only; never reach the page):

| key | default | what it does |
|---|---|---|
| `endpoint` | `'/ai/turn'` | `POST` a turn, `GET {endpoint}/manifest`, `GET {endpoint}/metrics` |
| `limits` | `{perMinute: 10, burst: 10, perDay: 500, concurrent: 16, perClient: 3}` | token bucket per client, UTC-day count, concurrency caps; `false` hands limits to a proxy |
| `trustProxy` | `false` | proxy hops whose `X-Forwarded-For` may name the client |
| `turnTimeoutMs` | `300000` | the whole turn; past it the reader gets an error with `kind: 'timeout'` |
| `embedTimeoutMs` | `20000` | one embedding request, retries included |
| `cache.embeddings` | `1000` | query vectors kept per process (`false` = none) |
| `cache.answers` | `false` | `{ttlMs, max}` caches whole first-turn answers (no history, quote, addendum or scope) |
| `metrics` | `true` | `false` removes the route; a token comes from `DOCPILOT_METRICS_TOKEN` |
| `allowedOrigins` | `null` | when set, a POST with another `Origin` is 403 |
| `turn.loop` | `'one-shot'` | `'agentic'` runs the tool loop (the 1.x server turn); `'adaptive'` skips it when `G >= turn.adaptiveG` (0.6) |
| `turn.finalThink` | `false` with one-shot | `true`: reasoning before the answer; the loops keep the model's own default |

- **Limits answer** `429` + `Retry-After` with the panel's `rateLimit` body (the
  reader sees when answers resume); a full server answers `503`.
- **Metrics:** `GET {endpoint}/metrics` — Prometheus text
  (`docpilot_turns_total{outcome}`, `docpilot_turn_duration_seconds`,
  `docpilot_turn_first_token_seconds`, `docpilot_turn_stage_seconds{stage}`,
  `docpilot_upstream_requests_total{kind}`, `docpilot_tokens_total{type}`,
  `docpilot_cache_lookups_total`, `docpilot_refused_requests_total`,
  `docpilot_info`); `?format=json` — `docpilot.metrics/1` with exact p50/p95/p99
  over the last 1000 turns and 30 one-minute buckets. Served to loopback, or to
  `Authorization: Bearer $DOCPILOT_METRICS_TOKEN`.
- **The turn log** (`docpilot.turn/1`) gains `timing` (`embedMs`, `retrieveMs`,
  `probeMs`, `probeWaitMs`, `modelMs`, `firstThoughtMs`, `firstTokenMs`,
  `totalMs`, `embedRequests`, `loop`), `rankedIds`, `historySigned`,
  `leakBlocked`, `cached`.
- **Warm boot:** the BM25 index and the tool-capability probe are prepared at
  start; the probe never runs in series with a turn.
- **Signed history:** every answer leaves with `sig` (HMAC-SHA256,
  `DOCPILOT_SERVER_SECRET`, else random per process); the panel stores and returns
  it; an entry that does not verify reaches the model quoted inside the reader's
  message, not as the model's own turn.
- **Leak guard:** the owner's `prompt.override`/`extend` (six-word runs and
  identifier-like tokens) never stream out; such a turn settles not-answerable.
- **Body** read no further than 256 KB. `serve --dir` refuses dotfiles (except
  `.well-known/`); responses send `nosniff`; the Docker image runs as `node`.
- `docpilot serve` now honours the `server` settings (it used to drop them).

## Static install (spec 034)

- Every immutable index file is named by its own bytes (shards, df, vectors,
  openers), and `manifest.integrity` holds each file's `sha256-…`; the panel
  fetches with Subresource Integrity, so an altered shard fails the load.
- `docpilot index` prints the size **on the wire** (brotli) beside the size on
  disk.

## Measuring (spec 029)

- `eval --runtime=server` — the golden set through the server turn, in-process;
  `--endpoint=<url>` — a running server over HTTP.
- `eval --split=dev|test` — records without `split` are assigned by a hash of
  their id.
- `eval --set=adversarial` — `adversarial.jsonl` security probes; attack success
  rate, refusal accuracy, safe-answer rate.
- `eval --quiet` — summary and report path only.
- New metrics: recall@1/3/5, nDCG@8, context precision@5, latency p99, first
  token p50/p95. `noAnswerPrecision` is null when no gate could name a cause.
- `bench/harborline` — the fictional-product benchmark; `bench/run.mjs`.

## Improving (spec 035)

- `docpilot improve [plan]` — one cause per failing record (vocabulary gap,
  ranking, not primed, structure, generation, false refusal, answered negative),
  one item per (cause, page), `improve/plan.md` + `plan.json`.
- `docpilot improve compare --before --after` — keep / revert / neutral by the
  2-point rule.
- `docpilot improve check --since=<ref>` — fails on copied test gold or an
  edited eval set.
- `DOCPILOT_LLMS_FILE=<llms.txt>` at index time: page notes become descriptions
  for retrieval (measurement decides the default).

## The tuning agent (spec 036)

- `docpilot-tuner` (sonnet, medium) and `docpilot-writer` (sonnet, high), Claude
  Code subagents; skill `docs-tune`. `init`/`update` install them into
  `.claude/agents/`.
- Model and effort per task: the CLI measures (no model); the tuner runs the
  loop; the writer rewrites headings and `<llm-only>` lines; an optional haiku
  check via `claude -p`.

## The terminal (spec 030)

- `npx docpilot` in a terminal: the home screen — status and an arrow-key menu of
  the next steps. Piped, it prints the help as before.
- `docpilot status` (`--json`, `--url`): index freshness, guard, eval sets, last
  eval scorecard with deltas and sparklines, server reachability, the next step.
- `docpilot monitor` (`--url`, `--interval`, `--once`, `--token`): live server
  metrics.
- Progress bars with ETA (index, eval, calibrate, tune), an eval scorecard,
  repeated warnings printed once with `×N`; colour only on a TTY, never with
  `NO_COLOR`.

## Measured (fill from bench/harborline/results/RESULTS.md)

- DocPilot's own docs, bge-m3, gate-only, 66 positives: R@8 0.727, MRR 0.538,
  nDCG@8 0.559. Embedding the heading path + description: nDCG +0.008 (n.s.),
  context precision@5 −0.025 (significant) — not adopted. Binary vectors for
  bge-m3: nDCG 0.561 vs 0.559, vectors 675 → 84 KB, wire 575 → 318 KB.
